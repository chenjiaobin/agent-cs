# 验收清单（贯穿全系列）

这份清单是第 1 篇定的规矩。后面每篇交付时对着它看一眼，做不到就不算完成。

## v0.1 · 立项（本篇）

- [ ] 仓库能 `pnpm install` 且 `pnpm build` 通过
- [ ] `node scripts/smoke.mjs` 能打到 DeepSeek，并打印首字延迟
- [ ] 关掉思考模式后，首字延迟明显低于开着（脚本会自动对比）
- [ ] `docker compose up -d` 后能连上 Postgres，`\dx` 能看到 vector 扩展
- [ ] 依赖版本写死在 package.json，不用 `latest`

## 全系列验收线（第 13 篇要全绿）

| 维度 | 标准 | 谁来保证 |
|---|---|---|
| 准确率 | 20 条真实问题，答对 ≥ 16 条 | 第 5、10 篇 |
| 成本 | 单次对话 ≤ 0.01 元 | 第 11 篇 |
| 延迟 | 首字 P95 ≤ 2s，整轮 P95 ≤ 8s | 第 2、11 篇 |
| 兜底 | 答不出来必须能转人工，不许硬编 | 第 8 篇 |
| 隔离 | 租户之间数据零串号 | 第 9 篇 |
| 可回滚 | 每次发布有灰度与降级开关 | 第 13 篇 |

## 为什么先写这份清单

因为"能聊两句"太容易了。接上模型、丢一个输入框，半小时就能演示。

但没有验收标准的项目，没有终点，也就没有第二次迭代。90% 的 Agent 项目死在这里——不是技术不行，是没人说得清"怎样算做完"。

清单越早定，后面越省事：第 10 篇的评测集、第 11 篇的成本看板，都是在给这张表填数。
